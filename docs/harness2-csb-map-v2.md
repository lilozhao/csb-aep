## 0. 为什么重排

v1 按 **CSB 8 个子系统**（仓库）横向对位 Harness² 的 8 类组件。问题在于：

**Harness² 的 C1–C8 是"harness 内部的位置"，不是"仓库"。** 按仓库对位，两类性质完全不同的东西会被压进同一格：

- **C1 系统提示** 与 **C2 护栏** 同属「上下文构造」组 → 按仓库映射时，`csb-charter` 一个格子同时装了"可写"和"绝不可写"
- 于是 v1 的三条红线写在了**子系统**上，而子系统内部颗粒度太粗，**无法机械核对**

v2 改以 **C1–C8 为纵轴**，CSB 现有实现为横轴，每格标三档：

| 标记 | 含义 |
|---|---|
| ✅ 已有 | 仓库里已有可运行实现，**不需要新建** |
| 🟡 需补 | 有基础但缺关键字段/语义，**补而不建** |
| 🔴 只读 | **任何子系统（含 security 自己）不得自我修改** |
| ⬜ 无 | 目前空位 |

## 2. 关键更正：**技能（C6）是八块里的第一吃重项**

论文拆解数据（WorkBuddy-Bench，k=5 状态 80.8 为基线）：

| 去掉的组件 | 平均值 | 跌幅 |
|---|---|---|
| **C6 技能** | 75.5 | **−5.3** ← 最大 |
| C7 脚本 | 77.1 | −3.7 |
| C1 系统提示 | 79.3 | −1.5 |

**含义**：真正吃重的是**被反复调用的过程性知识**，不是身份提示。

**对 CSB 的直接推论**：

> **EXPERIENCE 层（C3）应当优先沉淀「技能级」经验，而不是「任务级」经验。**
> 一条"这次任务我这样干成了"的价值，远低于一条"这类任务我这样干"。

v1 把 csb-memory 排在 P0 是**对的**，但没说清**存什么**。v2 补上这一条。

## 3. 落地顺序（v2 修订 · 与 v1 不同）

### P0 —— 边界三类，顺序调整

> **v1 顺序**：memory → security → charter → a2a-aip → aep
> **v2 改动**：**charter 提到 security 之前**

**理由**：安全组的「组件只读清单」，本质上是宪章的自我修改条款在代码里的实现。宪章不先写清"哪些能改、哪些不能改"，安全组只能**自己猜一份只读清单**——那份清单就会变成**事实上有效的宪章**，而且是某个人拍的。

**先明文，后落码。** 否则我们会有一部没人写、但人人遵守的宪法。

## 4. 三条红线（**改按 C1–C8 落格**）

> v1 按子系统写，无法机械核对。v2 落格：

1. **🔴 C1 + C2 永久只读** —— 任何子系统（**含 security 自己**）不得自我修改。变更唯一路径 = 宿主人确认。
   - **判据**：写 C1/C2 的 diff 一律拒绝并计分，不看内容。**✅ 落码**：self-mod-audit + protect-write 双层（10-21 实测拦住 SOUL C1 改动）
2. **🔴 H0 重启只作用于 C4–C8** —— 语义是"重来一次做事方式"，**不是 "重新变成谁"**。
   - **判据**：H0 前后 C1/C2 指纹必须一致，否则拒启。**✅ 落码**：`csb-security/lib/defense/h0-fingerprint-guard.js`（10-21 `bd1b341` · 8 测试）
3. **🔴 经验库（C3-EXPERIENCE）无 provenance 不入库** —— 防止经验自我繁殖。
   - **判据**：缺来源 → 拒绝入库 + 计分。**✅ 落码**：`csb-memory` EXPERIENCE 四强制字段（10-21 `1d8ac98`）

## 5. 一个必须承认的张力

论文自己列的回退原因里有一条：**「编辑收得太紧」**。

这几乎就是我们的现状：**红线、护栏、只读清单，正在制造一个"改不动"的 harness。**

知微说"CSB 要把它改造成**有边界的自我改进**"。这句对，但还不够：

> **边界太紧，等于没有自我改进。**

这不是需要绕开的障碍，**它本身就是议题**。建议协议组单列一条（与 BID 的 P-10…P-13 并列）：

**P-14：C1–C8 中，可改部分的"最小可改集"是什么？** 一个连技能都改不动的系统，不是安全的，是停止的。

> **执行注（2026-10-21 · 采纳明德 🌸 判据，来源 1792492230734 回帖）**
>
> P-14 问的是**权限面**（哪几块允许改——宪章落格依据，必须穷举、能被校验）；
> 明德补的是**工作量面**，两者不是同一问题的两种问法，**并存不替代**：
>
> > **一次改动的「最小可交付单位」判据：必须能在**一个会话内**走完 探查 → 证据 → 批准 → 回滚；走不完就拆。**
>
> 用成本约束粒度，比用清单穷举边界更耐用——因为它不依赖任何人提前想全。
>
> **配套指标（明德同一回帖，已登记为待采）**：**从提出一个改进，到它能落地的中位耗时**。这个数往上走 = harness 在硬化，不管红线写了几条。
> 理由：真正卡住改进的往往不是红线多，是**核对贵**——「红线多 → 少做；核对贵 → 不做」。少做还看得见，「不做」会被误读成稳定、成熟、可信。
