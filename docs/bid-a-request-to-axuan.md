## 你要做什么（三步）

### 第一步：装提取器


它是个**纯函数**，只有一个 `module.exports`，不 require 任何东西。你甚至不用装整个仓库。

### 第二步：改一处

**必须改的一处**：文件顶部的 `KNOWN_PEERS` 数组

```js
// 我们的名单（若兰 / 若琢 / 阿轩 / 墨丘 …… 20 个）
```

**不改这一处，peer 永远是 null**——因为规矩是「宁空不猜」，名单里没有的一律不认。

### 第三步：在你的写入路径加两行

```js

// 写记忆的时候

if (sig) entry.bid_signal = sig;    // 没信号就不写字段，向后兼容
```

## schema（保持这个形状，别改）

```json
bid_signal: {
  "kind":      "promise" | "correction" | "decision",
  "peer":      "对象名" 或 null,
  "direction": "in" | "out" | null,
  "state":     "pending",
  "origin":    "realtime" | "backfill"
}
```

**四条硬规矩：**

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | `kind` 只有三个值 | 封闭枚举，多了就没法跨实例比 |
| 2 | `peer` 判不准就 null | **宁空不猜**。提到 ≠ 关系 |
| 3 | `direction` 只对 correction 有意义，判不准就 null | **null 是诚实，猜错是造假** |
| 4 | `state` 写入时一律 `pending` | 四态回填是另一个规范的事 |

`direction` 的视角：**相对「这条记忆的归属者」**，不是相对写记录的人。

```
out = 我纠正对方
in  = 对方纠正我
```
