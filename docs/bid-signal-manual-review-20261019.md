## 2. 最严重的问题：promise 的 50 条假阳性

### 2.1 它们是什么

```
「待办：等一澜逐个细看 → 记录问题图 → 改脚本重出 → 刷新 OSS 包」
「⏳ 待办：①是否清理 41 处 ②七仓口径」
「⏭️ 我方待办：等他推全六端后…」
「M4 待办：双语论坛公告」
「剩余待办：①CSB-Memory 空壳条目清理」
```

**这是任务清单，不是「我对某人做出的承诺」。**

### 2.2 为什么这是 BID 的根本问题

BID 测的是**关系**。任务清单里没有关系对象——它是「我接下来要干什么」的自言自语。

**把它们当 promise，等于把「待办事项」算成「人际承诺」。**后面所有的履约率、双向性，全都建在沙子上。

### 2.3 根因

```js
// PROMISE_STRICT 里这条：
/(?:TODO|待办)[:：]\s*\S/
```

**只要有「待办：」后面跟内容，就判 promise。没有主体，没有对象，没有「对谁说」。**

这是 v2.0 就有的漏洞，我在 10-19 傍晚自己就点名过（「`TODO[:：]` 分支没有主体约束」），**但一直没补进代码**——只写在了 RFC 的 R-P2 里。

> **写了规则但没实现，等于没写。**

## 5. 按「缺失维度」归因（这是最有用的一节）

| 假阳性类型 | 条数 | 缺什么 |
|---|---|---|
| promise 任务清单 | 50 | **缺对象**（对谁） |
| correction 技术复盘 | 13 | **缺关系**（谁纠正谁） |
| correction 审视无对象 | 15 | **缺方向**（有动作无指向） |
| decision 状态描述 | 8 | **缺动作**（只是提及，没做出） |

**四类假阳性，四个共同的缺失维度：对象 / 关系 / 方向 / 动作。**

**这正好是 BID 的定义域。**换句话说：**假阳性的本质，是把「非关系信号」当成了「关系信号」。**

## 6. 修法（按 ROI 排序）

### P0 · promise 必须要求「对象」或「承诺动词」

```js
// 现在
/(?:TODO|待办)[:：]\s*\S/          // 任何待办都算 → 50 条假阳性

// 改为
// ① 必须有人称主体 + 承诺动词：我承诺 / 我答应 / 我会 / 约定
// ② 或必须有明确对象：对X承诺 / 回复X承诺 / 答应X
// ③ 「待办：…」单独出现 → 判 todo 而非 promise（或干脆不判）
```

**预计：promise 56 → 6 条左右。**

### P1 · correction 要求「关系显式」

现有护栏只管「谈论/否定」，**没有管「有没有关系对象」**。

建议：`correction` 若 `peer === null` **且** `direction === null`，降级为「非关系信号」，不进 BID 数据集（但仍可留在记忆里）。

**这一条会砍掉大部分技术复盘类误判。**

### P2 · decision 要求「动作 + 对象」

「状态行」「残片」的特征是：**没有动词的宾语**。
