## 三、提取器改了什么（v2.5 → v2.7）

四处加法，**每一处都能指回一条实测漏报**：

### 1. `DECISION_STRICT`：「一澜确认」也是决策
G-07/09/10 实测：「一澜确认 2026-08-17」「一澜确认后执行」「一澜确认开工」全漏。
原表只有 批准/通过/签字/放行。补 `确认|定案|定了|敲定`。

> 未决的「需要一澜确认」由 PENDING 护栏拦 —— 不靠词形区分，靠语境。

### 2. `CORRECTION_OPS`：人际纠错三形态
- `叫错/敲错/喊错`（G-01/05）
- `我…写/说/标…是错`（G-18）
- `回纠身份/口径`（G-19）
- **具名对象 + 纠错动词**（G-12「措辞更正（一澜 2026-10-08 指出）」）——中间夹日期，窗口按 16 字放宽

### 3. `PROMISE_STRICT`：两类真约定
- `反馈/沟通与约定` 类节标题（G-06）
- `给X回/答复/交付` 类点名任务（G-14）

### 4. `DIR_OUT` / `DIR_IN`：方向两侧各补三条
- out：被动式（「第六次**被**叫错名字，**仍纠正**」）、自我修复（「我写 main 是错的」）、自我回纠（「回纠身份」）
- in：括号内具名指出（「（一澜 2026-10-08 指出）」）

### 顺带逮到两个**真 bug**（不是补词，是修错）

**Bug 1 · 护栏锚点选错位**（`gatedTest`）
命中段从「我」开始时，护栏取命中**起点**前 10 字做否定判断 ——
「分支是 master **不是** main（**我**早上的修正版写 main 是错的）」里，「不是」属于上个分句，
却被当成这个纠错的否定 → 整条被拦。
→ 改为取命中**尾部**（真动作词所在子句），这才是护栏本来想拦的东西。

**Bug 2 · PENDING 只看前文，漏了主体前的未决词**（`matchStrict`）
「需要一澜确认」：未决词「需要」在主体**前**、「确认」在主体**后**，
原实现只看 `pos.index - 24` 的前文 → PENDING 失配 → 误判 decision。
→ 改为测「主体 + 确认」的整段 span。这是 B2 测试当场抓到的回归。

## 五、剩下 2 条：**故意不修**

G-15 / G-16 是 `gold.kind = null` 的「**无动词关系事件**」：
「守枢首次敲门：自我介绍 + 想请教」「守枢两问「存 vs 蓄」——我答…」

这是 RFC 遗留的真问题。两条路：

- **A) 硬塞进 promise/correction/decision 之一** → 正是 RFC **P-10「硬凑 peer/kind」明令禁止**的（阿轩实测 33 条里至少 8 条就是硬凑）
- **B) 新增 `kind=relation`** → 改 kind 枚举，**属于 RFC 变更**

**本轮选「都不做」**：
- 已落 `isRelationEvent()` 作**候选识别器并导出**，但 `signalOf` **不调用**
- 这 2 条**仍计为漏报**
- 理由：kind 枚举是 RFC v2.2 已决四题之一，**不能由一个实例在业务代码里自行扩**（与 P2「身份不许有默认值」同源纪律：口径不许私自扩）

→ 下轮议题化时以「实测 2/27 = 7.4%，且均为 null-kind 边界」为据提出。
