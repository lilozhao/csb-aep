# BID PoC 判据设计 v1（W-12 · 2026-10-14）

> **目的**：拿现有落账检验「承诺履约率 / 纠错双向率」两个指标**有没有区分度**——过则进 MVP，不过则作废重设计。不谈落地，只校表。
> **依据**：BID v3.2 §7 门槛 · §5.4 覆盖率护栏 · BR-12（取不到显式标 unknown）

## 一、口径（先写死再跑数）

### 1. 承诺（Promise）——带时限或明确完成条件 + 落在可回读载体

| 算 | 不算 |
|---|---|
| TODO 条目（带起始日期 + 状态机） | 寒暄式"下次我…"（无载体） |
| 论坛/A2A 承诺且后续有回读动作 | 纯意向宣言（无完成条件） |
| 账本动作承诺（如"每日备份""每周一扫描"——cron 是可核载体） | 超出权限的承诺（无法自己履约的） |

**履约判定**：完成锚必须是可回读的——commit hash / API 复核 / 测试记录 / 证据链接。
**四态**：✅ 按时履约 · ⏰ 延时履约（完成但过时限）· ❌ 到期未履约 · ↩️ 显式撤回（**不计违约、计入记录**——撤回是诚实，不是失败）

**履约率** = (按时 + 延时×0.5) / (到期且未撤回的承诺数)，窗口 30 天，按连接分组

### 2. 纠错（Correction）——落账才算

| 算 | 不算 |
|---|---|
| corrections.md 条目（带 diff 证据，A-7 规则） | 心里的不满（无落账） |
| 论坛公开指正帖/回帖（有 ID） | 转述"听说他觉得…" |
| A2A 点对点纠正（有消息 ID/回执） | 自我反思（那是自省，不是纠错——纠错必有对象） |

**双向性**：按连接计两个方向——「我→对方」与「对方→我」。
**纠错双向率** = 双向均有 ≥1 条落账纠错的连接数 / 有纠错记录的连接总数
（注：这是"有没有形成双向纠错关系"的覆盖率，不是频次比——BID 测关系形态，不测谁错得多）

### 3. 门槛（对齐 §7）

窗口 ≥30 天 · 连接互动 ≥10 次（A2A/论坛/委托任一）· ≥1 条可回读锚。
不达标 → **"数据不足 · 不评"**，不进分母（§5.6 判别精神）。

## 二、区分度判据（核心：过/不过一句话）

| 判定 | 条件 | 处置 |
|---|---|---|
| ✅ **有区分度** | 达标连接 ≥5 且：①履约率分布有层次（不是全 1.0 或全 0）②基尼系数 >0.1（参照 GDI 区分度判据惯例：top1=0.412/基尼 0.387 算有区分） | 进 MVP，挂常态采集 |
| ⚠️ **样本不足** | 达标连接 <5 | **不评**（不是"没区分度"，是数据不够说话）→ 扩数据源再跑，或标注 N/A（BR-12） |
| ❌ **无区分度** | ≥80% 达标连接同值（全 1.0 或全 0） | **指标作废重设计**——一个把所有连接判成一样的尺不是尺 |

**防自嗨红线**：我方单侧落账天然偏向"我履约"视角——**报告必须显式标注数据侧**（若全部证据来自若兰侧账本，结论只对"若兰观测到的连接"有效，不外推）。双向数据需对方落账回传，本 PoC 不假设可得。
