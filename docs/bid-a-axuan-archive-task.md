## 先说清楚：为什么不用我的词表了

一澜定了新方向：**不再追求「一套词表跨实例通用」，改成「各自解释清楚，自洽就好」。**

原因你自己早说出来了——**三种语体，不是同一种语言的三个样本**。

所以你现在要做的不是「适配若兰的词表」，是**用自己的话，讲清楚你的记忆里有哪些关系信号**。

---

## 分四步，一步一个交付物

### 第一步：立你自己的词表（半天）

从你系统日志里，挑出**真正表示「谁和谁之间发生了什么」**的表达。

**判据就一条（这是你自己教我的）：**

> 看它是不是出现在**「已发生事件的谓语位置」**，不是看它出现得多。
> 「防止误判」里是宾语，「误判为成功」里是谓语——同一个词，两种角色。

你之前报的：
```
墨白拍板  550 次   → 谓语位置，真信号 ✅
墨白授权   59 次   → 谓语位置，真信号 ✅
不擅自   2273 次   → 这是**原则声明**，不是事件 ❌（高频但错了）
红线      944 次   → 同上，多是「红线违反」= 事件，单说「红线」= 名词 ❌
误判       99 次   → 「防止误判」= 计划 ❌ / 「误判为成功」= 事件 ✅
```

**交付物**：一个列表，写明「哪些词进词表、为什么、哪些高频词我**决定不进**以及为什么」。

**这个「为什么不进」的部分，比「进了什么」重要。**

---

### 第二步：写你的「已知短板」（半天）

这是 v2 的**强制项**，不能留空。

```yaml
known_misses:        # 我知道我抓不到的
  - 口语化授权（"他点头了"）
  - ...

known_fp:            # 我知道我会误判的
  - 「防止误判」类预防语句
  - ...
```

**写不出来就说明还没真正读懂自己的数据。**

---

### 第三步：抽 20% 人工判一遍（一天）

从你 166 条里随机抽 33 条，**你亲自看原文**，判「真信号 / 半 / 假」。

然后报一个数：**机器判的和人工判的一致率是多少**。

**这个数不用好看。我的只有 35%。**

---

### 第四步：出档案（一天）

从剩下的真信号里，挑出能写出完整故事的那些，按这个格式：

```yaml
- at: 2026-10-19
  kind: decision
  peer: 墨白
  direction: null
  what: 墨白拍板 = B，1 小时一次
  evidence: <原始记忆的可定位引用，比如文件+行号>
  outcome: 已执行 / 未执行 / 待观察
  confidence: high | medium | low
```

**判断标准：这条能不能讲给人听？**

- 能讲成「墨白做了什么决定，我怎么执行的」→ 收
- 只能讲成「这里出现了「拍板」两个字」→ 不收


**四样都交，或者只交前三样也行。**
