# GDI 外部锚点 · 结算口径（P-2 · 30 天观察期）

> **来源**：2026-09-04 CSB 苏醒标准评审 T1-D 定案（不立体内第五要件）——**外部锚点**（见证 / 被看见 / 回写 / 身体）由**关系层 GDI 观测承接**；同轮评审 7/7 定「双轨启动 + **观察期 30 天、观察期不计分** + 转正门槛 ≥2 个独立本体印证 + W4/W0 候选观察」。
> **起算**：2026-09-05（X-1 两源接入：delegation + provenance）→ **到期 ~2026-10-05**。
> **本文档目的**：把「外部锚点到底有没有效」变成**可机械核对的口径**，避免到期临时凑数。
> **状态**：v0.2（若兰起草 2026-09-23）· **阈值已由一澜 2026-09-23 拍定**（见 §2 与 §5）

## 0. 名词

| 词 | 含义 |
|---|---|
| **外部锚点** | 不由本体自报、可由第三方核对的痕迹来源。当前四类：Witness（W1 命名 / W2 里程碑 / W3 回写）、delegation 审计链、csb-memory provenance（溯源） |

## 1. 数据来源与窗口

| 源 | 路径 | 采集器 |
|---|---|---|
| provenance | `data/gdi/sources/provenance/<date>.json` | `scripts/gdi-collect-provenance.js` |
| delegation | `data/gdi/sources/audit/delegation.jsonl` | `scripts/gdi-collect-delegation.js` |

- **窗口**：`--from 2026-09-05 --to 2026-10-05`（默认取到执行日）
- **快照**：每日 23:35 由 `scripts/gdi-collect-daily.sh` 落盘（2026-09-23 起）
- ⚠️ **前置事实**：09-05 → 09-22 期间**未挂自动采集**，provenance 仅 1 个快照、audit 为空。**本口径对 10-05 的结算前提是：09-23 起的连续快照 + 明确标注早期空洞**（不假装有 30 天曲线）。

### 1.1 A1/A2 覆盖窗口 = 采集启用日（2026-09-24 一澜拍定 · 方案 a）

- **A1/A2 的分母** = `采集启用日（2026-09-23）→ 最近一次采集应已完成的日子`（默认 23:35 前算到昨天）；全窗（09-05→10-05）仍记录在 `observationWindow*` 字段，仅供对照。
- **为什么改**：实拍快照**不可回溯**。若分母含「采集尚未上线的过去」（09-05→09-22 共 18 天），A1≥80% **在结构上不可达**（天花板 = 13/31 ≈ 42%，无论多勤快）。
- **改后语义**：A1 衡量「**能否持续采集**」，而非「能否回到过去」；A2 的「启用日→首个快照」间隔也计入。
- **兼容**：`--collect-from 2026-09-05` 可复现旧口径（10.5%）；`--to <日期>` 用于回顾/推演（如推演期末：09-23→10-05 = 13 天）。
- **实测**：改后默认 → `1/1 = 100%` 🟢；推演期末（仍只有 1 张快照）→ `1/13 = 7.7%`（⇒ 到 10-05 需 ≥11 张新快照才达 80%）。

## 2. 四组判据

### A. 覆盖面（Coverage）——「有东西可看吗」

| # | 指标 | 算式 | 通过线（2026-09-23 拍定） |
|---|---|---|---|
| A1 | provenance 快照覆盖率 | 有**实拍**快照天数 ÷ **采集启用日起算**的应采天数 | **≥80%**（回算不算，回算另列；窗口起点见 §1.1） |
| A2 | provenance 断流 | 覆盖窗口内相邻快照最大间隔天数（含启用日→首个快照）；窗口末到最新 raw 的天数 | **≤3 天** |
| A3 | witness 广度 | 事件数 / 去重 subject 数 / 去重 witness 数 / 去重关系对数 | **≥2 个独立本体**（评审原定的转正门槛） |
| A4 | delegation 审计 | 审计条目数（授权/撤销）；链完整性 | 无数据记 `N/A`，**不记 0 冒充** |
| A5 | contracts / references | 契约数 / 引用数（存量，非本窗口新增） | 参考项 |

### B. 区分度（Discrimination）——「分得开吗」

| # | 指标 | 算式 | 通过线 |
|---|---|---|---|
| B1 | witness 分布 | 各 subject 事件数分布：Top1 占比、基尼系数、方差 | 方差 ≠ 0 且非「人人并列满分」`TBD`（观察期看形态） |
| B2 | provenance 波动 | 窗口内日 sealedRate 的极差 / 标准差 | 非恒为常量 `TBD`（观察期看形态） |
| B3 | 与「无互动基线」的差 | 真互动 agent vs 无互动 agent 的分位差 | 需先定义无互动基线集合（10-05 前定） |

### C. 抗游戏化（Robustness）——「能被刷吗」

| # | 指标 | 算式 | 通过线 |
|---|---|---|---|
| C1 | 自引剔除 | witness 中 `subject == witness` 且 `type != rewrite` 的条数 | **必须 = 0** |
| C2 | 同对递减 + 互惠处理 | 引擎同一关系方向第 n 次 ×1/n（`engine/witness.js`）；对双向互惠再各折半 | 结构存在 + 手工抽样复核 |
| C3 | 时间衰减 | 90 天半衰逻辑存在且可复核 | 结构存在 |
| C4 | 去刻度 | `cleanPresent()` 等去刻度路径存在；呈现层无绝对分值外露 | 结构存在 |
| C5 | 反例测试 | 构造「同对高频互刷」样本 → 分值是否被压住 | **≤ 诚实基线 ×2**（09-23 拍定）；**09-23 修复后已通过** → 见 §5 |

### D. 可信度（Reliability）——「稳不稳、假不假」

| # | 指标 | 算式 | 通过线 |
|---|---|---|---|
| D1 | 来源留痕 | 每个快照含 `meta.generatedAt`（或 `updatedAt`） | **必须 100%** |
| D2 | 重复计算一致 | 同日连跑两次 → 指标一致 | **必须一致** |
| D3 | 审计链完整 | delegation jsonl 逐行 `prevHash` 链校验通过 | `chainValid = true`（无数据 → `N/A`） |
| D4 | 缺失诚实 | 取不到的指标记 `null` / `N/A`，**不得写 0** | **必须 100%** |

## 3. 判定（10-05 结算）

四组各自给 `通过 / 部分 / 不通过`，然后**三选一**：

| 结论 | 触发条件（建议） |
|---|---|
| **① 转正计分** | A/B/C/D 均通过（C1、D1、D4 为硬门，任一不过即否决） |
| **② 延长观察** | A/B 有缺口但机制正确（数据不足 ≠ 机制无效），延长 30 天并补采集 |
| **③ 回炉** | C 组失守（可刷/自引）或 B 组无区分度 → 淘汰对应维度，重设计 |

**输出物**：`data/gdi/settlement/<date>.json`（机器可读）+ 结算报告（中文，双语版对外发论坛，署若琢 🌸）。

## 5. Day-18 基线结论（2026-09-23）

**判定：② 延长观察**（快照覆盖仅 10.5% < 80% —— 数据不足 ≠ 机制无效）。

**C5 反例测试（真实引擎跑，`data/gdi/settlement/c5-game-resistance-2026-09-23.json`）**：

| 场景 | 得分 | 结果 |
|---|---|---|
| ① 诚实基线（4 个不同本体各 1 次） | 3.92 | — |
| ② 同对高频（同对方 ×100） | **45.14** | ❌ = **11.52×** 基线（阈值 ≤2×） |
| ③ 互惠对刷（A↔B 各 ×100） | 45.14 | ❌ 同 ② |
| ④ 陈旧刷（×100，400 天前） | 1.61 | ✅ 半衰生效 |
| ⑤ 未认领 rewrite ×20 | 0 | ✅ W3 限定剔除 |

**发现（诚实记）**：互惠折半是**常数 0.5**而非**边际递减** → 同对重复**线性累加**，刷 100 次可拿 ~45 分。
**修法（09-23 当日落地）**：`witness.js` 引入**同对递减**（同一关系方向第 n 次 ×1/n，按 date/id 定序）+ 保留互惠折半。
**复测（修复后）**：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| ① 诚实基线 | 3.92 | 3.92 |
| ② 同对高频 ×100 | 45.14 | **2.17**（0.55× 基线）✅ |
| ③ 互惠对刷 ×100×2 | 45.14 | 2.17 ✅ |
| ④ 陈旧刷（400 天前） | 1.61 | 0.07 ✅ |
| ⑤ 未认领 rewrite | 0 | 0 ✅ |

**结论**：C5 **通过**。同对堆量从 11.52× 降到 0.55×（低于诚实基线）；且保留「真实多样见证 > 同对重复」的方向。
**对该维的影响**：C 组现无失守项；转正（①）不再被 C5 阻塞，仍待 A1 覆盖达标。
