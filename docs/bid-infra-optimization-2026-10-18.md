## 1. 落地暴露的新情况（实测，非推测）

### 🔴 新情况 1：数据几乎全是「若兰一个人的」

| 事实 | 数字 |
|---|---|
| 全部记忆条目 | 4708 |
| 其中 `若兰.md` | **4663（99%）** |
| 其余所有 agent 合计 | 45 |

**含义**：所谓「覆盖率 1.9%」实际是「若兰自己的 1.9%」。
BID 测的是**连接级关系**（双向、互塑），单边数据**从结构上算不出 D3 双向性**。

> 这不是代码问题，是**数据布局问题**：`data/a2a-memories/` 里 99% 是本地主实例自己的记忆，
> 其他 agent 的记忆在他们的机器上。要算关系，必须跨实例取数或建立「关系级」数据视图。

### 🔴 新情况 2：存量 91 条里 31% 是误报

用 v2.0 词表重判存量：

```
仍判同类   63
降级为无关 28   ← 误报
改判他类    0
→ 存量误报率 31%
```

原因：这 91 条大多是**v1.0 词表在 10-15~10-18 采集的旧数据**，v2.0 只在**新写入**时生效，**存量未重判**。

### 🟡 新情况 3：`peer` 解析 ≈ 提及，不是关系

```
peer 非 null 46 / 91（51%）
```

人工抽查：`[prom/若琢] 来源链条：...若琢 09-01 回帖承诺...` —— 这条是在**引用**若琢的旧承诺，
不是若兰与若琢之间的承诺。**「提到名字」被当成了「有关系」**。

这是 10-15 就记下的苗头（「peer 过解析」），至今**未修**。

### 🟡 新情况 4：`direction` 形同虚设

```
direction 非 null 1 / 91（1%）
```

D3 双向性的核心原料是 direction，但 91 条里只有 1 条判出方向。**按现有数据，D3 恒为「测不出」**。

### 🟡 新情况 5：正文平均只有 88 字

```
daily-sync  4528 条 · 平均 88 字 · 带信号 1.8%
dream        180 条 · 平均 110 字
```

88 字的正文里，上下文不足以判断「这是谈论还是表达」。**信号判定的信息量本身不足**。

### 🟡 新情况 6：123 组重复正文

```
「溢出告警：无（memory-overflow-alert.js EXIT=0，无输出）」× 6
「判断：安全——纯哲学邀约…」× 4
```

同一句话被记多次 → 若带信号，会**重复计入分母**，虚增统计量。

### 🟡 新情况 7：`origin=realtime` 的 29 条无一条来自 v2.0

v2.0 于 10-18 16:18 上线，今天记忆尚未写入（0 条）。
**v2.0 的真实效果，要到今晚 23:50 蒸馏后才看得到**——现在所有读数都是 v1.0 的遗产。

## 3. O9 值得单说：数据模型的错位

这是落地中发现的**最深的问题**，值得单独说：

```
现在的模型：  记忆条目 --bid_signal--> {kind, peer}
BID 需要的：  连接(agentA ↔ agentB) --聚合--> {承诺数, 履约数, 双向率}

中间缺的是：  「条目 → 连接」的稳定映射 + 时间窗口聚合
```

现在 `peer` 只是个字符串，而且是**从正文里猜的**。
一个连接可能因为正文里随口提了一句就被建立，也可能因为没提就被漏掉。

**这解释了为什么四态回填命中 0**：回填要找「这条承诺后来完成了吗」，
但现在的数据模型**根本不知道这条承诺属于哪段关系**。

> 结论：O9 不是「优化」，是**基础设施真正的地基**。没有它，后面所有计算都在流沙上。

## 4. 我的建议

**先做 P0 四件（O1–O4），再谈 P1。**

理由：

1. **P0 全部能在现有数据上验证**，不依赖新采集，今天做完今天见数
2. **O1 的收益最直接**：清掉 31% 误报后，才能看清 v2.0 到底有没有用
3. **O4 是护栏**：它的价值是防止后续有人拿错数据算分，越早越好
4. **P1 的 O6 涉及隐私**（跨实例取数），必须先过同意原则，不能顺手做

至于 O9（关系级数据模型）——我认为它是**三期真正该讨论的主题**，
比「L2/L3/L4 取证层」更根本：取证层是往外拿数据，O9 是决定数据怎么组织。
