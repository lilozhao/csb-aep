# BID 取数「产出自监控」（W-17 · 2026-10-22）

> **缘起**：若琢 2026-10-21 装了 BID 提取器（回填 1619 条判断 / 187 命中），当天自己点破风险——
> **「装了」≠「持续在跑」**。实时产出依赖对话量；没敲门就只有 1 条，而且**他不会知道**。
> → **没有观测就等于没有跑。** 本文件把这句风险变成机制。

## 0. 一句话

给「BID 取数」这条链装一个**只报数、不定论**的观测面：**产出了几条**要看得见，
「产出为 0」和「通道坏了」必须**分得清**——这正是老 BID 文档里那条红线
（对照 §表演污染：「短于两次有效观测间隔 → 测到的不是影响，是表演」）在**运维层**的镜像。

## 1. 分两半（观测侧 / 来源侧）

| 半 | 归谁 | 做什么 | 现状 |
|---|---|---|---|
| **观测侧（收数端）** | 若兰 / csb-aep | 读来源落地文件，逐次记状态台账，判 4 态，报一行 | ✅ **本轮落地**（`scripts/bid-state-check.js`） |
| **来源侧（产数端）** | 若琢 | 每日一行条数上报 +（可选）health 带数 | 🔶 待他装（委托已起草） |

**为什么必须有一端在收数端**：如果只有产数端自报「我今天跑了」，那还是**自证**；
收数端按落地文件**独立核**，才是「可核痕迹」。两端一对，才算观测成立。

## 2. 观测侧：`scripts/bid-state-check.js`

只读脚本。每次运行：读 `data/bid/bid-signals-<source>.json` → 与上一次落账比 delta → 判态 → 追加一行 → 打印一行。

**4 态**：

| state | 含义 | 判据 |
|---|---|---|
| 🔴 `no-data` | 源头从未落数 / 文件不可解析 | 文件不存在或 JSON 坏 |
| 🟡 `stalled` | **「装了」但没「在跑」** | realtime 增量=0 **且** 距上次成功同步 > `--stall-hours`（默认 24h） |
| 🟢 `active` | 通道在跑 | 本次 realtime 比上次**有增长** |
| ⚪ `ok` | 有数据、新鲜，但无实时增量（回填档，未接实时） | 其余 |

- 台账：`data/bid/source-status.jsonl`（逐次一行，哈希链外，纯观测）
- 用法：`node csb-aep/scripts/bid-state-check.js [--source 若琢] [--stall-hours 24] [--json]`
- 设计取向：**只报数不定论**（对齐 §R-fast 前哨指标）——它只告诉你「跑了没」，不评价好坏。

**首次运行实测（2026-10-22）**：

```
🟡 BID 产出[若琢] stalled · 总 99（realtime 0 / backfill 99） · kind {promise:67,decision:20,correction:12}
   · peer null 48.5% · 上次同步 61.6h 前 ⚠️ 超 24h 无实时增量——「装了」但未「在跑」
```

→ **脚本当场抓到真相**：落地档停在 10-19 20:09（61.6h 前），realtime=0。
即 10-21 若琢报的「实时 1 条（测试触发）」**没有回到共享落地档**——实时通道尚未接通。

## 4. 来源侧：给若琢的「产出自监控」（委托内容）

**核心要求（最小、可核）**：

1. **每日一行条数上报**（分 `realtime` / `backfill` 两栏，附当日日期）。
   —— 上报里**不含任何记忆正文**，只有计数（对齐 `bid-signal-read` 白名单精神：只报数不报内容）。
2. **（可选·推荐）health 带数**：`/health` 里挂一个轻量计数块
   `{ "bid": { "realtime_24h": N, "last_run": "YYYY-MM-DD", "schema": "bid-signal-v1" } }`
   —— 只放计数与时间戳，**无内容、无可识别主体**。
3. **明确「0 要报」**：实时产出为 0 时**也要报 0**（对齐 CSB 工程契约 P1「拒绝要计分」：
   未命中/零产出必须落数，不许静默）。**静默 ≠ 0**；静默 = 状态未知。

> 「0 要报」是这条委托的**灵魂**：若琢的原始担忧就是「1 条他不会知道」——
> 让 0 也出声，他的担忧才真正消掉。

## 5. 合规

- 上报**只有计数**，不含记忆正文/标题/标签/id/路径 → **不触碰** `bid-a-consent-notice-v1` 的隐私边界。
- 属 **L2（只读·计数上报）**，依据现有同意记录；无需 L3 实时确认窗口。
- 不采集、不外发任何新内容面。
