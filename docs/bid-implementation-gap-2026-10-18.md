## 2. 已实现部分（A）明细

### A. 采集 · 记忆信号字段

| 项 | 内容 |
|---|---|
| 规格出处 | SPEC-MEM-0001（v2.0）· SPEC-MEM-0002 |
| 代码 | `csb-memory/lib/core/bid-signal.js`（抽取）· `bid-state.js`（四态回填 + 反抽） |
| 产出字段 | `bid_signal: {kind, peer, direction, state}` + `origin` |
| 当前读数 | 带信号 **91 / 4708（1.9%）** |
| kind 分布 | decision 16 · promise 67 · correction 8 |
| state 分布 | **pending 91**（无一条进入终态） |
| direction 非 null | **1 条** |
| peer 非 null | 46 条 |

**这条实现的实际能力**：能给单条记忆标注「这是一句承诺/纠错/决策，涉及谁」。
**不能做的事**：判断这句承诺后来履约没有（回填命中锚 0）。

### 该条自身的三个已知缺口

1. **覆盖率 1.9%** — 4708 条里只有 91 条带信号，绝大多数记忆无信号
2. **state 全 pending** — 四态回填在真实数据上命中 0，因现有 promise 多为「讨论/待办」而非真承诺
3. **direction 近乎全空** — 91 条里只有 1 条判出方向，双向率（D3）无原料

## 3. v3.2 主体：三维 + 余量

### D1 · 方向性（权重 40% · 四尺各 10%）

| 尺 | 规格要求 | 现有数据能否支撑 | 状态 |
|---|---|---|---|
| 反谄媚（顶/纠正被保留） | L2 决策日志 + L3 分歧记录 | 部分（有 correction 信号 8 条） | ❌ 未实现 |
| 反依赖（推回真人） | L4 出口率 | **无数据** | ❌ |

> **注**：四把尺全部需要 **L2/L3/L4** 取证层，而这三层都没接。即便强行算，分母也接近零。

### D2 · 影响程度（35%）= 痕迹 × 时长 × 不可逆性

| 不可逆性（沉淀为默认值） | SOUL/AGENTS 变更追踪 | ⚠️ 有受保护文件留痕，未接入 |

## 5. 关键落差排序（按阻塞强度）

| 排名 | 落差 | 为什么阻塞 | 修它需要 |
|---|---|---|---|
| **1** | **L2/L3/L4 取证层未接** | 三维、前哨、UM 全部依赖取证层；没有它算不出任何指标 | 新一期 spec（采集扩展） |
| **2** | **前置门槛未编码** | 门槛是地板：没编码就能"硬评"，直接违反 §7 | S 级（单函数 + 测试） |
| **3** | 信号覆盖率 1.9% | 分母太小，任何比率都不稳 | 依赖 1 |
| **4** | state 全 pending | 履约率分子恒为 0 | 依赖 1 + 真承诺样本 |
| **5** | 节奏层全空 | 没有双时钟就没有"多久评一次" | 新一期 spec |

## 6. 建议的后续分期（供讨论，非定论）

> 按「先有不违反红线的数据 → 再算 → 再定节奏」的顺序排，避免倒着建。

| 期 | 内容 | 依赖 | 前置条件 |
|---|---|---|---|
| **三期（建议）** | **L2/L3/L4 取证层接线** | 无 | 需 spec |
| 四期（建议） | 门槛编码 + 漏斗留痕 | 三期 | S 级可先行 |
| 五期（建议） | 三维计算 + UM | 三期、四期 | 需 spec |
| 六期（建议） | v3.3 双时钟 + 前哨 + 熔断 | 五期 | 需 spec |

**注**：三期/四期可并行——门槛编码不依赖取证层数据（它只判断"够不够"，不判断"好不好"）。
这也是唯一一件**现在就能做**的事，且做完立刻降低"硬评"风险。
