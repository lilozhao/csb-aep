## 一、decision 误判：根因是「未来时当成完成时」

你标了 6–7 条存疑，我逐条核，**实际误判 6 条**：

```
「等一澜拍板」        → 判了 decision  ← 错：还没决定
「需要一澜确认」      → 判了 decision  ← 错：还没决定
「等确认后转发」      → 判了 decision  ← 错：还没决定
```

**六个里五个是同一个原因。**`DECISION_STRICT` 里的「批准/通过/签字/确认」**不区分「已批准」和「等批准」**。

**修法**：新增未来时护栏。决策词处于 `等/待/需/应…确认|拍板|批准|决定` 语境 → 不判。

## 二、direction 反转：根因是「主语缺位」

你估 1–2 条反了。我逐条核，**实际反了 5 条**，全是同一件事：

```
「澈第三次叫错名字「若兰」→ 第三次纠正」
                              ↑ 这句话没有主语
```

**"纠正"这个动作，主语是我，不是澈。**但原规则是：

```js
// 旧：已知连接名 + 纠错动作（只要共现就判 in）
'(?:澈|若兰|...).{0,4}(?:纠正|指出|更正)'
```

**"对方名 + 纠错词"共现 ≠ "对方发出纠错动作"。**这条规则判得太宽。

**修法**：要求主动作标记（主动/已/当场/向我/对我），或名字与动作之间无其他动词插入。

同时反向也补了一条：**「澈主动指出我方错误」以前会被判成 out**（因为命中 `我方` → 走的 out 规则）。现在加了反义排除，正确判 `in`。

## 三、还查出一个你没提的问题：人际纠错判不出来

```
「一澜指出措辞」            → 原来完全不判 correction
「明德指出他从未见过该变量」 → 原来完全不判 correction
```

原因：`CORRECTION_STRICT` 只认「我方 + 纠错动作」，**对方纠正我方的动作根本不在里面**——只有 `DIR_IN` 认，但 `DIR_IN` 得先判出 correction 才有意义。是个死循环。

你 12 条 correction 里，至少有 2 条是靠别的线索捞回来的，**纯"对方指出我"的句子会整条漏掉。**

**修法**：补两条独立线索（`OTHER_CORRECTS_ME` / `SELF_CORRECTS_OTHER`）。
