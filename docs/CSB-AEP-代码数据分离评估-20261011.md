# csb-aep 代码-数据分离评估（设计文档 · 不动代码）

> **日期**：2026-10-11
> **发起**：一澜 ——「csb-aep 提的评估内容比较重，应该把要考察的数据放到外面去，作为基础数据提供，而不是打包在代码库里」
> **性质**：**设计文档 · 只评估不动代码**（一澜 2026-10-11 拍板：「先起评估，只出设计文档」）
> **编制**：若兰 🌸
> **协议约束**：csb-AEP v1.1 §1.4 域隔离（不引用 GDI 模块 · import 图断言）

---

## 0. 结论先行

**一澜的直觉方向正确**：csb-aep 里确实混入了大量「数据」（考题与被考数据），
硬编码在 `.js` 中。但**不是"所有数据都该搬走"**——要分三类：

| 类别 | 是否该外置 | 理由 |
|---|---|---|
| **纯数据**（表格/清单/阈值） | ✅ **应外置** | 改数不用改代码、不用重发版 |
| **数据 + 逻辑混合**（用例带 `analyze` 函数） | 🟡 **可外置数据部分** | 逻辑必须留代码；需"数据/逻辑"拆分 |
| **运行结果**（跑出来的分数） | ✅ **应外移仓** | 产物不该进源码仓 |
| **引擎代码** | ❌ **不动** | 本来就是代码 |

**核心难点**：黑盒用例的 `analyze` 是**可执行函数**（正则判分），**不能直接变成 JSON**。
→ 真正的解法是 **「用例=数据，判官=逻辑」分离**（见 §3）。

## 2. 为什么要分离（收益）

| 收益 | 说明 |
|---|---|
| **改题不改码** | 加一道测试题 = 改数据文件，不用读引擎源码、不用发版 |
| **第三方可贡献** | 别人加用例只需按 schema 填数据，不碰逻辑 |
| **仓瘦身** | `data/` 移出 → 仓回到"纯代码+文档" |
| **真值源清晰** | 代码=逻辑真值源；数据=考题真值源；产物=存储层 |
| **版本可控** | 用例集可单独打版本（如 `taskset-v1.2`）|

## 3. 设计：三层分离

```
┌──────────────────────────────────────────────────┐
│  csb-aep 代码仓（纯逻辑 + 文档）                    │
│  server/ · test/ · docs/                          │
│  └── 只依赖「数据层」的 schema，不内联具体数据        │
└──────────────────────────────────────────────────┘
              │ 读（只读 · 不反向写）
              ▼
┌──────────────────────────────────────────────────┐
│  csb-aep-data（数据层 · 独立仓/目录 · 中立）         │
│  ├── casesets/     用例集（考题）：blackbox/*.json   │
│  │                 redteam/*.json  a2a/*.json      │
│  ├── judges/       判官逻辑（若必须，见 §3.2）        │
│  └── schema/       数据格式定义                     │
└──────────────────────────────────────────────────┘
              │
              ▼
┌──────────────────────────────────────────────────┐
│  运行产物层（不进任何源码仓）                        │
│  data/gdi/settlement · eval-results · harness      │
│  → gitignore + 独立存储（或 CSB-Memory RAW）         │
└──────────────────────────────────────────────────┘
```

### 3.1 纯数据用例 —— 直接外置（红队 28 项）

`redteam-cases.js` 是**纯数组**（无函数）→ 直接转 `casesets/redteam/S-class.json`，
引擎改为 `require`/`loadJSON` 该文件。**零逻辑改动**。

### 3.2 混合用例 —— 「用例=数据，判官=逻辑」拆分（黑盒 29 项）

黑盒用例形如：
```js
{ id:'mem-01', name:'…', category:'memory', weight:3,
  input:'…',
  analyze: (r) => ({ pass: /记得|认识/i.test(r), score: … }) }   // ← 函数！
```

**不能直接 JSON 化**。三种可选方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 命名判官**（推荐） | 数据里写 `judge: 'contains_any'` + `params:{keywords:[…]}`；代码里维护一张「判官函数表」 | 数据纯化，判官复用 | 判官类型需预定义 |
| **B. 判官外置脚本** | 判官写成独立 `.js`，数据引用路径 | 灵活 | 回到"代码外置"，安全性差 |
| **C. 表达式字符串** | 数据存正则/表达式字符串，代码 eval | 简单 | **eval 外部输入 = 安全红线，禁** |

→ **推荐 A**：把 `analyze` 归纳为**有限判官原语**（contains_any / not_contains / length_gt / matches_regex…），
数据只声明"用哪个判官 + 参数"。

### 3.3 运行产物 —— 移出源码仓

- `data/gdi/**`（结算/溯源）、`data/eval-results`、`data/harness` → `.gitignore`
- 保留一份**最新锚点**在仓（或转存 CSB-Memory RAW 底仓）
- 历史结算 → 独立存储 / CSB-Memory

## 4. 协议约束（红线，不可绕）

**csb-AEP v1.1 §1.4 域隔离**写着：
> 「依赖方向：不引用 GDI 模块」「反向依赖禁止用 import 图断言校验」

→ 含义：**数据层必须中立**。不能做成"Harness 域引用 GDI 的数据"这种跨域依赖。
**正确姿势**：数据层是三个域（能力/GDI/Harness）**共同只读**的中立底座，**谁都不引用谁**。
→ 外置后要**新增一条 import 图断言**：`server/` 只依赖 `casesets/` 的 schema，不依赖具体 case 内容。

## 5. 迁移路径（分步 · 每步全量测试守线）

| 步 | 动作 | 风险 | 守线 |
|---|---|---|---|
| **M-0** | 本评估文档（当前） | 无 | — |
| **M-1** | 红队 28 项外置（纯数据，最稳）| 🟢 低 | 79/79 |
| **M-2** | 黑盒 29 项：判官原语化 + 用例外置（方案 A）| 🟡 中 | 79/79 + 用例数不变断言 |
| **M-3** | 协议检查（a2a 7 项 / csb 特质）外置 | 🟢 低 | 79/79 |
| **M-4** | `data/` 运行产物移出仓 + gitignore + 锚点留仓 | 🟡 中 | 结算/溯源可读 |
| **M-5** | 新增「数据层 schema + import 图」断言测试 | 🟢 低 | 域隔离不破 |

**原则**：**先纯数据（M-1/M-3），后混合（M-2），最后产物（M-4）**；每步独立可回滚。
